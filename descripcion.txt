================================================================================
            PROYECTO: COPIA DE LA INTERFAZ TERMINAL DE OPENCODE
================================================================================

DESCRIPCIÓN GENERAL
================================================================================
Este proyecto consiste en desarrollar una aplicación de terminal (TUI) que replica 
la interfaz y funcionalidad principal de OpenCode (anomalyco/opencode), un agente 
de codificación de IA de código abierto. La aplicación será completamente 
funcional en cualquier terminal de Linux Debian, Arch, macOS (incluyendo Apple 
Silicon), y Windows, con la característica clave de poder conectarse a servicios 
de IA locales o externos mediante APIs compatibles con Ollama o el formato OpenAI.

OBJETIVOS DEL PROYECTO
================================================================================
1. Replicar la experiencia de usuario de OpenCode en un entorno TUI (Interfaz de 
   Usuario de Terminal).
2. Asegurar compatibilidad multiplataforma: Linux, macOS (Intel/Apple Silicon), 
   Windows.
3. Implementar conexión flexible a modelos de IA:
   * Servidor local de Ollama (http://localhost:11434)
   * APIs externas con formato OpenAI (GPT-4, GPT-3.5, etc.)
   * Cualquier proveedor compatible con el estándar OpenAI.
4. Mantener la naturaleza "provider-agnostic" de OpenCode[reference:0].
5. Ofrecer una experiencia optimizada para teclado y flujos de trabajo de 
   desarrollador que viven en la terminal[reference:1].

CARACTERÍSTICAS PRINCIPALES
================================================================================
* TUI interactivo con componentes visuales modernos (input box, área de chat, 
  lista de modelos, indicadores de estado).
* Soporte para múltiples conversaciones y contexto.
* Selección dinámica de modelos disponibles en el servidor conectado.
* Historial de conversaciones persistente.
* Comandos abreviados de teclado para acciones frecuentes.
* Configuración de endpoint, API key y modelo por defecto.
* Modo CLI alternativo para integración con scripts.
* Logging y manejo de errores robusto.

TECNOLOGÍAS RECOMENDADAS
================================================================================
Para la implementación se pueden elegir entre los siguientes stacks, todos 
compatibles con TUI moderno y APIs de IA:

Opción 1: GO + BUBBLE TEA
-------------------------------------------------------------------------------
- Lenguaje: Go (compilación cruzada nativa para todas las plataformas)
- Framework TUI: Bubble Tea (basado en The Elm Architecture)[reference:2]
- Componentes UI: Bubbles / Bubbles components
- Cliente HTTP: net/http estándar
- Ventajas: 
  * Excelente rendimiento
  * Binario estático único para cada plataforma
  * OpenCode original está escrito en Go[reference:3]
  * Framework maduro y usado en producción[reference:4]

Opción 2: RUST + RATATUI
-------------------------------------------------------------------------------
- Lenguaje: Rust (alto rendimiento y seguridad)
- Framework TUI: Ratatui (fork de tui-rs)[reference:5]
- Backend terminal: Crossterm (multiplataforma)[reference:6]
- Cliente HTTP: reqwest
- Ventajas:
  * Rendimiento excepcional
  * Tipado fuerte y seguridad de memoria
  * Ratatui es mantenido activamente
  * Experiencia moderna en Rust

Opción 3: PYTHON + TEXTUAL
-------------------------------------------------------------------------------
- Lenguaje: Python 3.7+
- Framework TUI: Textual[reference:7]
- Cliente HTTP: httpx o aiohttp (async)
- Ventajas:
  * Desarrollo rápido
  * Sintaxis familiar
  * Soporte multiplataforma probado (Linux, macOS, Windows)[reference:8]
  * CSS-like styling para la UI[reference:9]
  * Rico ecosistema de widgets[reference:10]

INTEGRACIÓN CON API DE IA (OLLAMA / OPENAI)
================================================================================
La aplicación se conectará a servicios de IA mediante:

Protocolos Soportados
-------------------------------------------------------------------------------
1. Ollama API nativa:
   * Endpoint: http://localhost:11434/api/generate
   * Endpoint: http://localhost:11434/api/chat
   * Métodos: POST con JSON
   * Autenticación: No requerida (local)

2. OpenAI-compatible API:
   * Endpoint configurable (ej: https://api.openai.com/v1/chat/completions)
   * Formato de mensajes estándar OpenAI
   * Soporte para API key
   * Base URL configurable para proxies o servicios alternativos

3. Proxy unificado (opcional):
   * Se puede implementar un pequeño proxy que traduzca entre formatos
   * Facilita el cambio entre proveedores sin modificar la app[reference:11]

Ejemplo de Configuración
-------------------------------------------------------------------------------
La aplicación leerá un archivo de configuración (JSON/YAML/TOML) como:

{
  "llm": {
    "provider": "ollama",           // "ollama", "openai", o "custom"
    "endpoint": "http://localhost:11434",
    "model": "llama3.2",
    "api_key": null,                // Solo para OpenAI
    "timeout": 60,
    "max_tokens": 2048,
    "temperature": 0.7
  },
  "ui": {
    "theme": "dark",
    "history_size": 100
  }
}

La aplicación deberá soportar autodescubrimiento de modelos desde endpoints 
OpenAI-compatible, como se ha propuesto para OpenCode[reference:12].

COMPATIBILIDAD MULTIPLATAFORMA DETALLADA
================================================================================
Requisitos para cada sistema operativo:

Linux (Debian / Arch)
-------------------------------------------------------------------------------
- Cualquier terminal moderna (GNOME Terminal, Konsole, Alacritty, Kitty, etc.)
- Dependencias mínimas: bibliotecas estándar de terminal
- En Debian: apt install <paquete>
- En Arch: pacman -S <paquete>
- La versión TUI funciona perfectamente en terminales emuladores estándar[reference:13]

macOS (Intel y Apple Silicon)
-------------------------------------------------------------------------------
- Terminal.app, iTerm2, Alacritty, Kitty, etc.
- Binario universal (x86_64 + arm64) para soporte nativo en Apple Silicon
- Sin dependencias adicionales
- La aplicación usa solo capacidades estándar de terminal POSIX

Windows
-------------------------------------------------------------------------------
- Windows Terminal, PowerShell, Git Bash, WSL
- Soporte para APIs de consola moderna (Virtual Terminal Sequences)
- Alternativamente, usar Crossterm que funciona con consolas Windows modernas
- Compatibilidad con cmd.exe limitada, se recomienda Windows Terminal

ARQUITECTURA DE LA APLICACIÓN
================================================================================
La aplicación seguirá una arquitectura cliente/servidor similar a OpenCode:

Componentes:
1. Módulo TUI: Maneja la interfaz de usuario y eventos de teclado.
2. Módulo de Configuración: Gestiona la configuración del usuario.
3. Módulo de API Client: Se conecta a Ollama/OpenAI y maneja peticiones.
4. Módulo de Persistencia: Guarda historial de conversaciones.
5. Módulo de Comandos: Procesa comandos especiales (/help, /model, /clear, etc.)

Flujo de datos:
[Usuario] -> [TUI] -> [Módulo de Comandos] -> [API Client] -> [Ollama/OpenAI]
                       ^                           |
                       |-----[Persistencia]<-------|

CONFIGURACIÓN Y USO (EJEMPLO)
================================================================================
Instalación
-------------------------------------------------------------------------------
# Linux (Debian/Arch) - si se empaqueta
sudo dpkg -i opencode-clone.deb
# o
sudo pacman -U opencode-clone.pkg.tar.zst

# macOS (Intel/Apple Silicon)
brew install opencode-clone

# Windows
# Descargar .exe o usar winget

# O simplemente ejecutar el binario:
./opencode-clone

Configuración inicial
-------------------------------------------------------------------------------
1. Al primer inicio, se crea ~/.config/opencode-clone/config.json
2. Editar para especificar proveedor y modelo:
   {
     "llm": {
       "provider": "ollama",
       "endpoint": "http://localhost:11434",
       "model": "llama3.2"
     }
   }
3. Asegurar que Ollama está corriendo: `ollama serve`

Uso básico
-------------------------------------------------------------------------------
$ opencode-clone
> ¡Hola! ¿En qué puedo ayudarte?
> /model llama3.2:70b
> Cambiando a modelo: llama3.2:70b
> /clear
> /exit

Atajos de teclado
-------------------------------------------------------------------------------
Ctrl+Enter    - Enviar mensaje
Ctrl+S        - Guardar conversación
Ctrl+L        - Limpiar pantalla
Ctrl+N        - Nueva conversación
Ctrl+Q / Esc  - Salir
Tab           - Autocompletar comandos
F1            - Ayuda

INTEGRACIÓN CON OLLAMA (DETALLES TÉCNICOS)
================================================================================
Ollama expone una API REST en http://localhost:11434[reference:14]:

Generación de texto (formato no chat):
POST /api/generate
{
  "model": "llama3.2",
  "prompt": "¿Cómo crear una TUI en Go?",
  "stream": true
}

Chat (conversación con contexto):
POST /api/chat
{
  "model": "llama3.2",
  "messages": [
    {"role": "user", "content": "Hola!"}
  ],
  "stream": true
}

La aplicación debe manejar streaming para mostrar respuestas en tiempo real.
Se puede usar cualquier cliente HTTP con soporte para Server-Sent Events (SSE).

NOTA SOBRE OPENCODE
================================================================================
OpenCode es un agente de codificación de IA de código abierto que se ejecuta en 
la terminal[reference:20]. Está construido por usuarios de neovim y los creadores de 
terminal.shop, con el objetivo de expandir los límites de lo posible en la 
terminal[reference:21]. Este proyecto propone una implementación alternativa que 
enfatiza la compatibilidad con Ollama y la simplicidad de configuración.
